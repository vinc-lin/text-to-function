# A Browser Instrument for the Scene Engine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** a local page that makes the Scene Engine's state observable at a glance and drivable by hand, so perception reads as live state rather than as a text table you re-print by typing a command.

**Non-goal:** replacing the CLI. This adds a way in.

**Stack:** Python stdlib only (`http.server`, `json`) plus one self-contained HTML file. Current runtime deps are `numpy` and `pyyaml` and this must not change them. No CDN, no framework, no build step.

---

## The rule that governs every decision here

**The UI is not a second path to the car.** Every action calls a method the CLI already calls. The Yes button submits the utterance `好` through `session.handle()` — it does not call `executor.execute`, and it does not reach into `SceneEngine.resolve()`'s internals.

The whole design rests on consent having exactly one shape and one route to the vehicle. A button wired to the executor would be a second route with different rules, which is what `VehicleFacts` was tightened to prevent. If a UI action cannot be expressed as an existing session call, that is a signal to stop and ask, not to add a shortcut.

## Architecture

One process. `python3 -m ui` builds a `Session` exactly as `python3 -m cli` does, then serves on localhost.

**Single-threaded, deliberately.** `sim/vehicle.py:17` opens SQLite with default thread affinity, so the connection may only be used from the thread that created it. Session construction, the server, and every request handler therefore run on the main thread. One request at a time is correct for a single-user instrument, and it avoids both loosening `check_same_thread` and bolting a request queue onto a system that does not need one. `ThreadingHTTPServer` is the wrong class here and using it will produce `ProgrammingError` on the first request that touches the car.

| file | responsibility |
|---|---|
| `ui/state.py` | pure `Session -> dict` snapshot. No I/O, no HTTP. This is the only part with tests. |
| `ui/actions.py` | the six actions, each a thin call onto `Session` |
| `ui/server.py` | routes, JSON encode/decode, error handling |
| `ui/__main__.py` | argument parsing, session construction, `serve_forever` |
| `ui/page.html` | the page, self-contained |

`ui/` is **not packaged** — `pyproject.toml`'s include list stays `t2f* eval* sim* scene*`, same treatment as `cli/`.

## The snapshot

`GET /state` returns exactly this. Everything in it is read from state that already exists; nothing is stored for the UI's benefit except `conversation`, which is presentation history and labelled as such.

```json
{
  "mode": "C_llm · shipped · S",
  "clock_offset": 0.0,
  "perception": [
    {"key": "inside.rear_occupant", "value": "child", "confidence": 0.9,
     "source": "cabin_cam", "age": 12.0, "expires_in": 288.0, "ttl": 300.0}
  ],
  "car": [{"entity": "window.all", "attribute": "window_child_lock", "value": true}],
  "rules": [
    {"rule_id": "rear_child_window_lock", "verdict": "near_miss",
     "reason": "inside.rear_occupant conf 0.60 in [0.50, 0.80)", "suppressed_by": ""}
  ],
  "fallback": "no model attached",
  "pending": {"scene": "rear_child_window_lock",
              "question": "后排有小孩，要打开儿童锁吗？", "expires_in": 24.0},
  "conversation": [{"who": "scene", "text": "后排有小孩，要打开儿童锁吗？"}],
  "log": [{"function": "set_window_child_lock", "outcome": "executed",
           "error": null, "detail": ""}]
}
```

**The pending question's text is not stored anywhere** — `PendingConsent` carries the scene id and the proposal, not the sentence. Recover it with `speech_for(rule.intent)` for the rule whose `id == pending.scene`. Do **not** add a field to `PendingConsent` to make this easier; the sentence already has one home and a second copy could disagree with it.

```python
"""The snapshot is the whole contract between the engine and the page."""
import pytest

from cli.session import Session
from ui.state import snapshot


@pytest.fixture
def session():
    return Session.build(fake=True, llm=False, gate="permissive")


def test_a_fresh_session_snapshots_cleanly(session):
    s = snapshot(session)
    assert s["perception"] == [] and s["rules"] == [] and s["car"] == []
    assert s["pending"] is None
    assert "S" in s["mode"]


def test_perception_carries_what_a_draining_bar_needs(session):
    session.observe("rear_occupant", "child", 0.9, ttl=30.0)
    row = snapshot(session)["perception"][0]
    assert row["key"] == "inside.rear_occupant" and row["value"] == "child"
    assert row["confidence"] == 0.9 and row["ttl"] == 30.0
    assert 0 < row["expires_in"] <= 30.0


def test_the_rules_pane_shows_every_rule_with_its_reason(session):
    session.observe("rear_occupant", "child", 0.6)
    rule = snapshot(session)["rules"][0]
    assert rule["verdict"] == "near_miss" and "0.60" in rule["reason"]


def test_a_pending_question_carries_its_sentence_and_a_countdown(session):
    """PendingConsent stores the scene and the proposal, never the sentence — it is
    recovered from the rule's intent so there is only ever one copy of it."""
    session.observe("rear_occupant", "child", 0.9)
    pending = snapshot(session)["pending"]
    assert pending["scene"] == "rear_child_window_lock"
    assert pending["question"] == "后排有小孩，要打开儿童锁吗？"
    assert 0 < pending["expires_in"] <= 30.0


def test_the_pending_question_clears_once_answered(session):
    session.observe("rear_occupant", "child", 0.9)
    session.handle("好")
    assert snapshot(session)["pending"] is None


def test_the_car_pane_shows_only_what_moved(session):
    assert snapshot(session)["car"] == []
    session.observe("rear_occupant", "child", 0.9)
    session.handle("好")
    car = snapshot(session)["car"]
    assert {"entity": "window.all", "attribute": "window_child_lock", "value": True} in car


def test_the_log_carries_the_cause_of_a_refusal(session):
    session.observe("rear_occupant", "child", 0.9)
    session.handle("好")
    session.handle("开车窗")
    refused = [r for r in snapshot(session)["log"] if r["outcome"] == "refused"]
    assert refused and refused[0]["detail"] == "车窗儿童锁已开启"


def test_the_clock_offset_is_reported(session):
    session.advance_clock(45.0)
    assert snapshot(session)["clock_offset"] == 45.0


def test_the_snapshot_is_json_serialisable(session):
    """It crosses the wire as JSON; a stray dataclass or Enum would 500 the page."""
    import json
    session.observe("rear_occupant", "child", 0.9)
    json.dumps(snapshot(session))


def test_the_snapshot_never_raises_on_a_half_built_session(session):
    """The page polls several times a second, including during a reset. One exception
    turns the whole instrument into a 500 and hides the state it exists to show."""
    session.scene = None
    s = snapshot(session)
    assert s["perception"] == [] and s["rules"] == []
```

```python
import pytest

from cli.session import Session
from ui.actions import ACTIONS, perform


@pytest.fixture
def session():
    return Session.build(fake=True, llm=False, gate="permissive")


def test_observe_records_a_perception_event(session):

                                 "confidence": 0.9, "ttl": 30.0})
    assert session.context_rows()[0].expires_in <= 30.0


def test_say_routes_an_utterance(session):
    out = perform(session, "say", {"utterance": "打开车窗儿童锁"})
    assert out["reply"]


def test_consent_goes_through_the_same_lexicon_as_the_cli(session):
    """The Yes button submits 好 as an utterance. It does not call the executor, and it
    does not reach into the engine — a second route to the car with different rules is
    exactly what this design forbids."""
    perform(session, "observe", {"key": "rear_occupant", "value": "child", "confidence": 0.9})
    perform(session, "say", {"utterance": "好"})
    assert ("window.all", "window_child_lock", True) in session.changed_signals()


def test_clock_advances(session):
    perform(session, "clock", {"seconds": 30.0})
    assert session.clock_offset == 30.0


def test_reset_clears_the_car_and_the_context(session):
    perform(session, "observe", {"key": "rear_occupant", "value": "child", "confidence": 0.9})
    perform(session, "say", {"utterance": "好"})
    perform(session, "reset", {})
    assert session.changed_signals() == [] and session.context_rows() == []

    with pytest.raises(KeyError):
        perform(session, "execute_tool_call", {"name": "unlock_doors"})
```

```python
import json

@pytest.fixture

    assert "perception" in json.loads(body)


def test_the_root_serves_the_page(session):
    status, ctype, body = handle_request(session, "GET", "/", b"")
    assert status == 200 and "html" in ctype
    assert b"<" in body


def test_an_action_posts_and_returns_the_new_state(session):
    body = json.dumps({"key": "rear_occupant", "value": "child", "confidence": 0.9}).encode()
    status, _, out = handle_request(session, "POST", "/action/observe", body)
    assert status == 200
    assert json.loads(out)["state"]["pending"]["scene"] == "rear_child_window_lock"


def test_an_unknown_path_is_404_not_a_traceback(session):
    assert handle_request(session, "GET", "/../../etc/passwd", b"")[0] == 404


def test_an_unknown_action_is_404(session):
    assert handle_request(session, "POST", "/action/execute", b"{}")[0] == 404


def test_malformed_json_is_400_not_a_500(session):
    assert handle_request(session, "POST", "/action/observe", b"{not json")[0] == 400


def test_an_action_that_raises_returns_400_and_keeps_the_session(session):
    """A bad input must not kill an instrument holding a minute of loaded models."""
    body = json.dumps({"key": "k", "value": "v", "confidence": "not a number"}).encode()
    status, _, _ = handle_request(session, "POST", "/action/observe", body)
    assert status == 400
    assert handle_request(session, "GET", "/state", b"")[0] == 200
```

`ui/actions.py` — `ACTIONS` is a dict of name → callable taking `(session, payload)`. Exactly five entries: `observe`, `say`, `clock`, `reset`, `scene_llm`. `perform(session, name, payload)` looks the name up and calls it; an unknown name raises `KeyError`. `say` returns `{"reply": turn.reply}`.

`ui/server.py` — `handle_request(session, method, path, body) -> (status, content_type, body_bytes)` is a **pure function of those arguments**, so every route is testable without a socket. The `BaseHTTPRequestHandler` subclass is a thin shell that calls it. `GET /` reads `ui/page.html` from disk. Malformed JSON is 400. An action that raises is 400 with the message, never a 500 and never a dead session.

`ui/__main__.py` — `--fake`, `--no-llm`, `--gate`, `--port` (default 8770), `--db`. Builds the session, prints the URL, `HTTPServer` (**not** `ThreadingHTTPServer`), `serve_forever` with a `KeyboardInterrupt` handler that exits cleanly.

## Task 3: the page

**Files:** create `ui/page.html`

One self-contained file. Inline CSS and JS, no external anything. A dark instrument palette — this is a diagnostic tool, not a product surface.

**Layout.** Header with the mode label, the clock offset, and controls (advance clock, toggle scene fallback, reset). Then three columns — **Perception**, **The car**, **Rules** — and a full-width **Conversation** below with the input box.

**Perception cards** are the heart of it. Each observation shows its key, value, source and confidence, plus a **TTL bar that drains continuously** — interpolated client-side between polls from `expires_in` and `ttl`, so it moves smoothly rather than stepping once a second. A bar under 20% turns amber. When an observation expires, its card fades out rather than vanishing, so you see it happen.

**Confidence** renders as a small filled bar next to the value, with the rule's threshold and floor marked, so a near-miss is visible as *position* rather than as a number to compare mentally.

**Rules** show a verdict badge — `match` green, `near_miss` amber, `reject` slate, `not_applicable` dim, `error` red — the reason in monospace, and `suppressed_by` as a strikethrough note when present. The fallback note sits under them.

**The car** lists signals that differ from seeded, each flashing briefly when it changes.

**Conversation** is a transcript with the driver's turns and the car's replies distinguished. When `pending` is non-null, a bar appears above the input with the question and a live countdown, plus **Yes** and **No** buttons that submit `好` and `不用` as utterances.

**Polling** every 400ms via `GET /state`. Actions POST and use the returned state immediately rather than waiting for the next poll.

Handle these honestly: an empty perception pane says "nothing observed", an empty car pane says "unchanged from seeded", and a failed fetch shows a disconnected banner rather than silently freezing on stale data.
