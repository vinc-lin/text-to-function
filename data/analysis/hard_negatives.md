## Interpretation

The confusions are **diffuse singletons** — there is no dominant confusable cluster to target with
discriminative prototypes (the only repeat is an OOD prototype out-competing `open_sunroof` twice,
which is an OOD-detection concern, not a sibling-confusion one). A few are genuine near-siblings
(front/rear fog light, volume/mute, wiper/rain-sensing-wiper), but each appears once on this dev
split, so adding hand-authored prototypes would be guessing rather than evidence-driven.

**Decision:** no catalog prototype additions this pass — the errors are not clustered enough to
justify targeted data authoring, and doing so risks overfitting the small dev split. Recall@1/@3 on
the test split are therefore unchanged from Spec 2 (0.814 / 0.907). The lever for recall remains a
larger, more diverse prototype set or a light embedder fine-tune (future work), not spot-fixes.
